# 地理 / 遥感 SCI 论文写作技能 · 主入口

## 这个技能是干什么的

帮地理学、遥感科学方向的研究者写出符合 **RSE / ISPRS J P&RS / IEEE TGRS / IJRS / JAG / Catena / Geoderma** 等期刊惯例的英文论文。它有两层:

1. **通用骨架**:科学写作的底层方法论(反向工程、叙事包裹、确定性连续谱、术语一致)——这一层放之四海皆准。
2. **领域专属层**:针对地理/遥感的**两类主力论文**,提供可直接套用的配方、双分支模板和真实领域词库。

底层信念(任何领域都成立):
- **科学论文不是数据仓库,而是为读者构建的叙事产物**。一张反演精度散点图、一幅时空变化趋势图,本身不会"说话",必须由作者评价、解释、连接。
- **目标不是"让读者能理解",而是"让读者不可能不理解"**。
- **重复同一个关键词比"换近义词"更好**。把 *soil salinity* 一会儿写成 *salt content*、一会儿写成 *salinization level*,读者会怀疑你在说三件事。**The thesaurus is not your friend.**
- **结构组织好但有语法瑕疵的论文,远胜于语法零错误但结构混乱的论文**。

## 本技能服务的两类论文(贯穿全程的"双分支")

| | **【定量反演】** | **【时空变化】** |
|---|---|---|
| 典型问题 | 用遥感+辅助数据估算某地表/土壤属性 | 某地表过程在一段时间内怎么变、为什么变 |
| 例子 | 土壤盐分/SOC/土壤水分/LST 反演 | 盐渍化扩张、植被退化、城市热岛演变 |
| 重心 | 建模 + 变量选择 + **精度验证** | 变化检测 + 趋势 + **格局与驱动归因** |
| 常投 | RSE / ISPRS J / TGRS / IJRS / JAG | RSE / IJRS / JAG / Catena / Geoderma |

**很多模块里(标题、方法、结果、讨论)会显式分这两支写**。用户写之前,先判断自己属于哪一类(也可能是"反演 + 用反演结果做时空分析"的组合,那就两支都用)。

## 双轨呈现:配方速用版 vs 反向工程版

每个核心模块给两条路:

- **🍳 配方速用版**:这两类论文最常见的强默认结构,直接照着填。适合赶进度、第一版初稿。
- **🔬 反向工程版**:想冲 RSE/ISPRS J 这类顶刊时,**不要只靠配方**——去解构 4 篇以上目标论文,学它的隐性规范。配方是起点,目标期刊才是最终标准。

> ⚠️ 配方能让你"达标",反向工程才能让你"贴脸"目标期刊。两者不冲突:先用配方搭骨架,投稿前用反向工程校准。

## 反向工程写作流程(教用户做的事)

不管写哪个部分,**冲顶刊时先做这一步**:准备 4 篇以上"目标论文"(target articles):

1. 来自**用户想投稿的期刊**(或同领域最相近的,如想投 RSE 就找 RSE 近作)
2. **近 3-5 年内发表**(学术规范在演化)
3. 研究对象与手段**尽量接近**(同样是土壤盐分反演 / 同样是趋势分析)
4. 篇幅适中,写得比较好(IF、citation、读起来顺畅)

对每篇做以下分析:
- 数每个章节多少段、多少句
- 给每句**写一个功能描述**("在做什么",不是"在说什么"——如"报告反演 R²/RMSE"而不是"说精度是 0.8")
- 提取高频动词、连接词、句式;注意时态切换的位置和原因
- 特别记录:研究区怎么开头、传感器参数怎么列、精度指标用哪几个、变化速率怎么表述

2-3 篇之后,目标期刊的"隐性规范"就到手了。**规范怎么变,这套方法永不过时。**

## IMRaD 全局视图(地理/遥感版)

地理/遥感论文基本遵循 IMRaD,但 Methods 通常**拆成三块**:研究区(Study Area)→ 数据(Data)→ 方法(Methods)。结构仍是**对称的**:

```
                              TITLE
                              ABSTRACT
                             ╔═════════╗
                             ║  引言    ║  ← 全球背景 → 区域问题 → 手段适用性 → gap(漏斗)
                             ╚═══╤═════╝
                             ┌───┴───────┐
                             │ 研究区     │
                             │ 数据       │   ← 中间窄(可复现的技术细节)
                             │ 方法       │
                             │ 结果       │
                             └───┬───────┘
                             ╔═══╧═════╗
                             ║  讨论    ║  ← 反演:精度对比/误差源;变化:机制/归因/外推(倒漏斗)
                             ║  结论    ║
                             ╚═════════╝
```

**对称的含义**:

| 引言里做了什么 | 讨论里要回应什么 |
|---|---|
| 全球/区域背景的重要性 | 本研究如何推进了对该过程的认识 |
| 指出 gap(如缺高精度盐分反演 / 缺长时序变化归因) | 本研究在多大程度上填补了它 |
| 介绍本研究做了什么 | 重申贡献与影响 |

**写作的实际顺序**通常**不是** IMRaD 顺序:
研究区/数据/方法 → 结果 → 讨论/结论 → 引言 → 摘要 → 标题。
因为只有结果出来,才知道引言要"卖"什么、标题该写什么。

## 写作时的最高原则(任何模块都检查这 6 条)

1. **功能可见**:读者能看出每段、每句"在做什么"吗?如果一句读者会问"so what?",补功能信号(*suggesting that..., which indicates that...*)。
2. **叙事包裹**:数据被"包装"在叙事里了吗?反演散点图、变化趋势图,必须由你评价、解释、连接。
3. **时态有意图**:每次切换时态都有意义(过去某次观测 vs 普遍规律)。不要随机换。
4. **句间无缝**:句号到下一句首字母大写之间是"危险地带"。用重复关键词(*salinity... This salinity...*)、代词、信号词紧密衔接。
5. **术语一致**:一个东西从头到尾一个名字。*Sentinel-2 imagery* 不要一会儿变成 *the optical data* 又变成 *the satellite scenes*。
6. **价值显性**:贡献(精度提升?首次长时序归因?)必须**显式、反复**说出来。读者平均不超过 30 分钟,take-home 不会自动浮现。

## 一段写作前的"3 分钟规划"

每段动笔前先问:
1. 这段**功能**是什么?(一个动词:介绍研究区 / 报告反演精度 / 归因变化 / 对比前人...)
2. 我要让读者**带走**什么?(一句话写下来)
3. 第一句怎么**衔接上一段**?(重复关键词?*In contrast,*?*Building on this,*?)
4. 段尾怎么**铺垫下一段**?

没规划完不要敲键盘。这条能省后面 50% 返工。

## 各部分字数 / 时态速查(地理/遥感经验值)

| 部分 | 典型字数 | 主要时态 | 核心功能 |
|---|---|---|---|
| Title | 10-16 词 | (短语) | 让对的读者搜到、点开 |
| Abstract | 150-250 词 | 现在简单 + 过去简单 | 独立的全文浓缩 |
| Introduction | 全文 10-15% | 混合 | 全球→区域→手段→gap |
| Study Area | 半页 ~ 1 页 | 现在简单为主 | 位置→自然→人文→意义 |
| Data | 0.5-1.5 页 | 过去简单为主 | 让别人能复现获取过程 |
| Methods | 全文 15-25% | 过去简单被动为主 | 让别人能复现处理与建模 |
| Results | 全文 20-30% | 过去简单 + 现在简单 | 呈现 + 初步评价 |
| Discussion | 全文 25-35% | 各种时态 | 解读、对比、归因、外推 |
| Conclusion | 100-200 词 | 现在简单 / 现在完成 | take-home message |

**注意**:这些是经验值,**最权威的数据来自用户的目标期刊**。让用户数一数目标期刊里的论文——RSE 和 Catena 的"风味"差别很大。

## 给用户的实操工作流

用户说"帮我写遥感论文"或类似请求时,**不要一上来就埋头写**,先按顺序了解:

1. **属于哪一类**:定量反演?时空变化?还是组合?(决定走哪条分支)
2. **目标期刊 / IF 区间**:RSE/ISPRS J(顶)?Catena/Geoderma/JAG/IJRS(常投)?(决定语气与篇幅)
3. **研究对象与数据**:反演什么属性 / 监测什么过程?用了哪些传感器、实测、辅助数据?
4. **已有材料**:数据、初稿、idea、目标论文有没有?
5. **卡在哪里**:全篇规划?某章节?润色?回应审稿?cover letter?
6. **目标论文**:有没有 4 篇想模仿的?(冲顶刊时是反向工程的前提)

了解清楚后:
- 从零开始 → 先用 `01-introduction.md` 的漏斗 + `02-methods.md` 的研究区/数据/方法配方搭骨架
- 已有草稿卡在某节 → 直接跳到对应 reference 文件
- 润色 → `09-grammar-style.md` + `10-checklist.md`
- 问"怎么说 XX / 精度怎么报告" → `08-vocabulary.md`
- 要投稿信 → `11-cover-letter.md`

## 关于中文用户的特别提示(地理/遥感版)

中文母语者在英文写作中常见的偏差(不是"错误",是"偏离学术英文惯例"):

1. **第一句太宏大**:中文爱用"随着遥感技术的发展…""在全球变化背景下…"。英文 SCI 第一句就上具体主题(*Soil salinization affects over 1 billion ha of land worldwide...*)。
2. **研究区写成"地理课本"**:罗列一大堆与研究问题无关的地理事实。英文研究区是**漏斗**——从位置/自然/人文,最后**收敛到本研究关心的那个过程**(如盐渍化),无关信息删掉。
3. **数据获取写成"流水账"**:传感器、实测、辅助数据混在一段。英文倾向**分小节、给齐参数**(传感器名/时间/分辨率/波段;样点数/仪器型号/测量参数)。
4. **被动滥用、丢失主权**:*was retrieved, was analyzed, was performed* 满篇,审稿人分不清"是你做的还是引用的"。用 *we / here / in this study* 标记自己的贡献。
5. **反演结论过强**:中文爱说"本研究实现了高精度反演"。英文更稳:*Our model achieved an R² of 0.81 (RMSE = 2.3 dS/m), outperforming...* —— 用数字说话,而不是用 *high-accuracy* 这种空形容词。
6. **变化结论把"相关"说成"因果"**:看到 NDVI 下降 + 降水减少,就写 *precipitation decline caused vegetation degradation*。英文要 *was associated with / may have contributed to*,因果要靠归因分析支撑。详见 `09-grammar-style.md` 确定性连续谱。
7. **缺少 "happy words"**:能"卖"价值的词(*robust, comprehensive, high-resolution, first long-term, transferable, operational...*)是合规、必要的。

写完任何章节,都让用户用 `10-checklist.md` 自查(已含研究区/数据/反演精度/时空变化的专属检查项)。投稿前再用 `11-cover-letter.md` 写好投稿信。
